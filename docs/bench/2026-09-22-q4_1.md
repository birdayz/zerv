## Verified before / after implementation

Independent goldens were generated before native code with pinned ggml 0.24.0,
456172ec-dirty, source 456172ec733a135778adcd32d00e576a58232e45. Every oracle output
matched independent Python half/nibble/arithmetic/FP32 packing exactly.

- Both finite half fields exhausted against 11 fixed partner fields and all
  unsigned coefficients: **1,396,736 blocks / 44,695,552 FP32 values**. Fingerprint:
  `de4f090e4d2b464c0e246328066d16e71aa0877f036df4a1bb43d8c60fb4597d`.
  This is not all 63,488² field pairs.
- Explicit all-packed-byte, all edge-pair, 1,024 seeded blocks, plus **64 actual
  blocks across all eight Q4_1 ffn_down tensors**, including row/end boundaries.
- Both scale/minimum fields and both block positions exhaust all 2,048 nonfinite
  encodings; errors preserve the entire output. Empty, unaligned and bad-size
  cases pass. Signed zeros/subnormals preserved; strict FP32, no approximate math.
- Golden regeneration is byte-identical, SHA256
  `e92a34a3b84584d71a931d99dbf411343e9a4f1cea25edf947bcf258ce436540`.
- **29/29 native tests pass Debug and ReleaseFast; 33/33 Python tests pass**.
  Original Q4_0/Q8_0 exhaustive gates are unchanged. Native benchmark is a static
  ELF with no dynamic NEEDED dependency. New API: q4_1 and explicit blockElements.

## Matched component setup

Actual bytes of `blk.0.ffn_down.weight`, dimensions [17408,5120], encoded 55,705,600
bytes. Complete model SHA verified on each run. Native GGUF loader and independent
ggml container oracle identify the same tensor. Full hashes of all decoded values
match the independent decoder for all three workloads in every trial.

Ryzen 9 3900X; Linux 7.2.6; CPU 10; existing powersave policy unchanged, no exclusive
host isolation. Zig 0.16.0 ReleaseFast/native. External test-only C adapter compiled
GCC16.2.1 O3/native, installed ggml library resolved/hash-checked. The installed
public ggml.h is byte-identical to the retained pinned header. Adapter resolves
`ggml_get_type_traits(Q4_1)->to_float` once outside timing; no Python per-call work.
OpenSSL is used only by the external adapter for hashes **outside timed loops**.
No C/C++/OpenSSL code enters the native runtime.

Both sides preallocate output, use readonly mapped input, perform synchronous
in-process decode and use compiler barriers. No allocation, hash, logging or I/O
inside timing. Native additionally prevalidates both half fields across the whole
row; the reference assumes valid input. This safety cost remains enabled.

Three warmups, seven trials, three alternating native/reference rounds: **21
observations per workload/engine/run**. Calls per trial: row 10,000, tile 256,
full tensor 4. Same warm/reused buffer policy; output hash after each trial.

| Rows | Engine | Min–max | Sample σ |
|---:|---|---:|---:|
| 1 | native | 1.980–2.552 | 0.167 |
| 1 | ggml | 2.801–2.994 | 0.048 |

| 5120 | native | 32858.723–38831.507 | 1786.244 |
| 5120 | ggml | 29599.427–35207.923 | 1626.099 |

Small-workload native advantage repeats. Full-tensor ranking reverses: native is
**8.3% slower on the repeat**, despite winning the first run. The working set
includes 356,515,840 output bytes. Host/cache/frequency variability is substantial;
no stable full-tensor speedup is claimed, and no causal explanation is established.
This comparison is diagnostic CPU decode, not a llama-server serving win. There is
no equivalent decode-only HTTP endpoint; actual server comparisons remain required
at the model and serving integration milestones.
