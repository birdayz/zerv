## Equivalent real-shape comparison

Same model bytes of blk.0.ssm_out.weight, [6144,5120], 21,626,880 packed bytes and
125,829,120 decoded bytes. Both engines use mapped readonly input and preallocated
output, direct synchronous calls, compiler barriers, no Python/alloc/hash/I/O inside
timing. External test-only C uses public ggml type traits -> to_float resolved once;
its decoder matches the independent full-workload hashes. Native retains extra
whole-row finite validation; the reference assumes valid scales.

CPU10, existing powersave policy, Ryzen9 3900X/Linux7.2.6; Zig0.16 ReleaseFast/native;
GCC16.2.1 O3/native adapter, installed ggml. Not exclusive host isolation. Identical
Q4_1 benchmark defaults remain supported. 3 warmups, 7 trials × 3 alternating rounds
=21 observations per engine/shape. Calls/trial: 10,000 row, 256 tile, 4 full tensor.
Exact model/library/header/compiler/dependency/source hashes and commands retained.

Native small rows/tiles are faster in both runs, but **full tensor is slower in
both** (4.3% first, 3.2% repeat). No whole-tensor or serving win claimed. The CPU
diagnostic implementation is accepted for correctness; GPU fused kernels have
separate future gates. There is no equivalent llama-server decode-only endpoint.

The expanded harness's Q4_1 default was also rerun with complete matching hashes.
Its current small-row/tile timings regressed relative to the historical Q4_1 runs:
3.541/225.293 µs native versus 2.769/180.562 µs reference; full tensor
31,835.928/29,115.315 µs. Source/benchmark code generation and environment are not
separated causally here; **do not carry forward the old small-Q4_1 speed claim to
this binary**. [Compatibility run](data/2026-09-22-q4_1-compatibility/manifest.json).
This measured regression is retained, not hidden by checking correctness alone.
