## Native contract

Extend `quant.Format` with q4_1. Same allocation-free, synchronous, caller-owned,
non-overlapping-buffer and byte-unaligned-input contract as Q4_0/Q8_0. Add explicit
`blockElements(format)` (32 for all currently supported formats); `blockBytes(q4_1)`
is 20. Empty rows succeed. Check encoded block length, exact output length, then
**both binary16 fields in every block before writing anything**. Any all-one
exponent in either field gives NonFiniteScale; signed zeros/subnormals are valid.

At offsets 0/2: LE half scale d/minimum m, converted exactly to binary32. At offset
4: 16 packed bytes. First 16 output values use low unsigned nibbles, next 16 use
high unsigned nibbles. Output = `f32(d * q) + m`, strict round-to-nearest binary32.
The half×0..15 product fits binary32 exactly; addition may round. Preserve signed
zero. Native/external/scalar comparisons must match **bits**, not a tolerance.
No quantization, dot products, GPU, model execution or new runtime dependency.

## Independent fixture generator

`tests/reference/generate_q4_1_goldens.py`: explicit external development command,
refuses overwrite. Bind pinned exported `dequantize_row_q4_1` with validated aligned
storage/counts. Verify every oracle result against independent Python `<e` unpack,
unsigned nibble arithmetic and `<f` packing before emitting expected data. Record
actual binary/version/dirty commit, generator and complete model SHA. GGUF tensor
positions come from the independent ggml container oracle, never the native loader.

Exhaustive fingerprint order: varying field d, then m; ascending finite binary16
bits (63,488), fixed other field in order
[0,0x8000,1,0x8001,0x03ff,0x0400,0x3c00,0xbc00,0x3555,0x7bff,0xfbff].
Payload byte j = j | ((15-j)<<4). This is 1,396,736 blocks / 44,695,552 values;
canonical LE FP32 SHA256. This exhausts each field separately against 11 partner
values and all coefficients, **not all 63,488² scale/minimum combinations**.

Explicit fixture rows: all 256 packed byte values in every lane, all 121 edge-field
pairs, 1,024 seeded independent random blocks, and 64 real-model blocks. For each
of eight tensors sample block indices 0,1,row_end,row_start_next,next+1,middle,
penultimate,last. Pin offsets/dimensions/input hashes. Golden regeneration is
explicit into a new file and must reproduce bytes. Native tests also exhaust all
2,048 nonfinite encodings in each field, including later-block failure atomicity,
length/output errors and unaligned/multiple blocks. Existing Q4_0/Q8_0 gates remain.

## Matched measurement contract

Use real bytes of blk.0.ffn_down.weight at shapes [17408,1], [17408,64],
[17408,5120]. Three warmups; seven trials, 10,000 / 256 / 4 calls per trial for
row/tile/full tensor. Three alternating native/reference process rounds, CPU 10,
ReleaseFast/native. Preallocated output, readonly mapped input, warm/reused buffers;
no allocations, hashes, logging, I/O or Python per-call overhead inside timing.

Native and **external test-only C adapter** use monotonic clocks and output compiler
barriers. Reference uses public `ggml_get_type_traits(GGML_TYPE_Q4_1)->to_float`,
resolved once outside loops (not a slower reimplementation). Installed ggml.h
exposes the synchronous function-pointer ABI; record its hash and library loader
resolution. Reference adapter may use installed OpenSSL SHA256 **outside timing**
only; this stays external tooling and never enters the native build/runtime.

Both engines emit full input/output SHA256, shape/counts and elapsed ns; independent
Python ctypes oracle additionally validates workload hashes. Validate every record
and fail missing/extra/duplicate/nonpositive/wrong-hash trials. Record model/library/
compiler/source identities, commands, exact offsets, actual raw trials/dispersion,
complete source snapshots and failures. Refuse existing run directories. Repeat.

Native includes whole-row finite-field validation; external decoder assumes valid
fields. This extra safety work remains enabled and is disclosed. This is a CPU
diagnostic decoder comparison, not fused matvec, GPU or llama-server inference.
There is no equivalent llama-server decode-only endpoint. Keep direct serving
comparisons as mandatory gates at later model/HTTP milestones.
